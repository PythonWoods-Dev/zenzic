## Description

The `.zenzic.toml` (or `pyproject.toml`) configuration file contains an invalid structure or a value of the wrong type (e.g. a string where an integer is required). An unknown key or section is not an error: it is reported as a warning that names it, and ignored.

When configuration validation fails, Zenzic halts document analysis to protect workspace integrity.

### A `docs_dir` that does not exist

Since v0.31.0 this code also covers a second, more common configuration error: **`docs_dir`
names a directory that is not there.**

That used to be `Z906 NO_FILES_FOUND` at exit `0` — the same answer given to a directory that
exists and is simply empty. The two are not the same situation. An empty directory is a project
in setup and nothing is wrong with it; a directory that does not exist means the scan examined
nothing, and reporting success over it is a green gate on an unexamined tree. Measured: `zenzic
init` followed by `check all` on a cloned Astro repository printed "Audit skipped" and exited
`0` over 2,604 sources it never read, because Astro keeps them under `src/content/docs` and the
default is `docs`.

When a documentation generator is detected in the repository, the message names it and the
directory that generator uses, rather than listing the possibilities.

### A declared engine whose file is not there

This code also covers the third configuration error of the same family: **you declared an
engine and the file it needs is missing.** The declaration had no effect, and without this
finding the run reports as though it had one.

The two halves differ only in where the absence is noticed:

| Engine | File it needs | Without it |
| --- | --- | --- |
| `prebuilt`, `vsm` | `.zenzic-vsm.json` | The adapter builds, and produces exactly what `standalone` produces |
| `zensical` | `zensical.toml` | The adapter cannot be built at all |
| `mkdocs` | `mkdocs.yml` / `mkdocs.yaml` | The adapter substitutes `standalone` and prints a notice on stderr |

`zenzic check`, `audit` and `guard` stop with this code and exit `1` in the first two rows.
They have somewhere to fail, and a run that analysed with an engine you did not ask for is
not a run you can gate on.

The editor cannot stop. A language server with no diagnostics on screen is
indistinguishable from a clean document, so it reports `Z111` against your configuration
file and keeps analysing with `standalone` — the diagnostic is also the warning that what
you see is not what CI will report. Before v0.31.0 a declared `zensical` with no
`zensical.toml` made the editor publish nothing at all, with the error going only to the
server's stderr log.

The `mkdocs` row is the remaining gap: that substitution is still announced on stderr only,
so neither the CLI nor the editor reports it as a finding.

## How to Fix

For an invalid key or value type, correct it in `.zenzic.toml` as indicated by the field error
in the diagnostic message.

For a missing `docs_dir`, set it to the directory that actually holds your Markdown sources:

```toml title=".zenzic.toml — Astro / Starlight"
docs_dir = "src/content/docs"
```

```toml title=".zenzic.toml — Docusaurus"
docs_dir = "docs"
```

`zenzic init` writes this line for you when it recognises the generator. If the directory
exists and is merely empty, you want [`Z906`](Z906.md) instead, and it is not an error.

For a declared engine with no file, either create the file the table above names — see
[Configure the adapter](../how-to/configure-adapter.md) — or declare
`engine = "standalone"` if this project has none to give.

## Example Error

```toml
# Invalid string type for integer setting
placeholder_max_words = "fifty"
```

Corrected `.zenzic.toml`:

```toml
placeholder_max_words = 50
```

## Why there is no runnable example

`Z111` is a **configuration-load error** — a schema type mismatch — on the same
path as [`Z001`](Z001.md). It is raised during parsing, before any Markdown is
read and before a findings payload exists, so the run aborts rather than
reporting, and an executable example has no output to assert against.

As with [`Z110`](Z110.md), its error panel prints the **absolute path of the
machine that ran it**, so a captured block would encode one developer's
filesystem.
