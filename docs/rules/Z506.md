# Z506: MALFORMED_FRONTMATTER

<div class="grid cards" markdown>

- :material-alert-circle:{ .lg .middle style="color: var(--zz-error);" } **Severity: Error**

    ---

    Penalty: **5.0 points** | Category: **`content`**

- :material-cog-sync-outline:{ .lg .middle style="color: var(--zz-terminal-meta);" } **Remediation & Opt-In**

    ---

    Auto-Fixable: **No** | Opt-In: **No**

## Rationale

This rule is triggered when the opening YAML frontmatter delimiter on line 1 of a file is malformed (such as using `--` instead of `---`), causing metadata directives to be parsed as raw body text.

---

## How to Fix

Inspect the flagged location in the Markdown file and update the content or configuration:

<div class="grid cards zz-pattern-pair" markdown>

- :material-close-circle:{ .lg .middle style="color: var(--zz-error);" } **Failing Pattern (Triggers Z506)**

    ---

    Line 1 opens the block with two dashes instead of three. The rule reads line 1 only,
    so nothing — not even a comment — may come before it:

    ```markdown title="docs/example.md"
    --
    title: "Invalid Frontmatter"
    ---
    ```

- :material-check-circle:{ .lg .middle style="color: var(--zz-success);" } **Passing Pattern (Resolves Z506)**

    ---

    Line 1 opens the block with exactly three dashes:

    ```markdown title="docs/example.md"
    ---
    title: "Valid Frontmatter"
    ---
    ```

</div>
