## Rationale

This governance rule is emitted when a suppression directive is placed where no violation of the code it names actually occurs.

Two forms trigger it. An inline comment — `<!-- zenzic:ignore: ZXXX -->`, or `{/* zenzic:ignore: ZXXX */}` in MDX — on a line carrying no such finding. Or a `data-zenzic-ignore` attribute on a tag that produces nothing the attribute covers.

### When the verdict is decided

`Z603` is decided **at the end of the scan**, not when the file is parsed. It has to be: a directive naming `Z101` is dead only if the link beside it resolves, and that is decided against the whole Virtual Site Map, after every file has been read. A directive is reported here only once every pass that could have consumed it has run.

This matters when reading output: `Z603` says "nothing in this entire scan was suppressed by this directive," which is a stronger statement than "nothing on this line."

### What `data-zenzic-ignore` covers

The attribute is tag-scoped rather than code-scoped, so what counts as "suppressing something" is the set of codes it is documented to cover:

| Tier | Codes | Covered |
| :--- | :--- | :--- |
| HTML hygiene | `Z120`–`Z124` | Yes |
| Relative links | `Z102`, `Z104`, `Z105` | Yes |
| Site map | `Z101` | No — decided against the VSM; use `.zenzic.toml` |
| Security | `Z202`, `Z203`, `Z205` | No — non-suppressible by any mechanism |

Two known limits, stated rather than left to be found:

- The directive is matched by **line**, not by tag. Two tags on one line, only one carrying the attribute, share the line's directives.
- The directive is **single-use**. A tag producing both a hygiene finding and a link finding spends its attribute on the first, and the second is still reported.

## How to Fix

Inspect the flagged location in the Markdown file and update the content or configuration:

### Bad (Triggers Z603)

```markdown title="docs/example.md"
<!-- BAD: Suppression directive on line with no Z511 violation -->
<!-- zenzic:ignore:Z511 -->
This is a short sentence.
```

### Good (Resolves Z603)

```markdown title="docs/example.md"
<!-- GOOD: Remove unneeded inline suppression comment -->
This is a short sentence.
```

# Preview the removal first (default: dry-run, shows a diff)
zenzic fix

zenzic fix --apply
