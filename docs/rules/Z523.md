# Z523: HEADING_ORDER_VIOLATION

<div class="grid cards" markdown>

- :material-alert-outline:{ .lg .middle style="color: #f59e0b;" } **Severity: Warning**

    ---

    Penalty: **2.0 points** | Category: **`content`**

- :material-cog-sync-outline:{ .lg .middle style="color: #64748b;" } **Remediation & Opt-In**

    ---

    Auto-Fixable: **No** | Opt-In: **Yes**

</div>

---

## Description

The headings in a document appear out of the mandatory sequential order specified in `[policies].required_heading_order`.

Standardizing the order of major sections (such as *Overview*, *Prerequisites*, *Installation*, *Usage*, *API Reference*) ensures consistent cognitive architecture across large documentation codebases.

---

## Configuration

Define the required heading sequence as a list of RE2 regex patterns in `.zenzic.toml`:

```toml title=".zenzic.toml"
[policies]
required_heading_order = [
    "^Overview$",
    "^Prerequisites$",
    "^Installation$",
    "^Usage$",
    "^API Reference$"
]
```

```toml title="pyproject.toml"
[tool.zenzic.policies]
required_heading_order = [
    "^Overview$",
    "^Prerequisites$",
    "^Installation$",
    "^Usage$",
    "^API Reference$"
]
```

Any matched heading must appear after earlier patterns in the sequence. Documents omitting optional sections remain valid as long as present sections follow ascending order.

---

## How to Fix

Reorder document sections to match the defined sequence:

```markdown
<!-- Before (API Reference precedes Overview) -->
# API Reference
...
# Overview
...

<!-- After (Overview precedes API Reference) -->
# Overview
...
# API Reference
...
```

---

## Suppression

Suppress this check for specific directories via `.zenzic.toml`:

```toml
[governance.directory_policies]
"notes/**" = ["Z523"]
```
