## Rationale

This rule is emitted prior to document scanning when `.zenzic.toml` contains invalid TOML syntax, malformed table headers, unclosed quotes, or data type mismatches (such as supplying a string where a boolean or array is expected).

An invalid configuration halts execution immediately (`Exit 1`) before any filesystem scan begins to prevent unpredictable behavior across the workspace.

---

## How to Fix

Correct the invalid TOML syntax or schema structure in `.zenzic.toml` (or `pyproject.toml`) as indicated by the diagnostic message. This rule fires before any Markdown file is read.

---

## Configuration

A type mismatch triggers Z001 — `fail_under` must be an integer, not a string:

```toml title=".zenzic.toml (invalid)"
fail_under = "ninety"  # invalid: expected an integer
```

Corrected:

```toml title=".zenzic.toml"
strict = true
fail_under = 90
```

## Why there is no runnable example

`Z001` is a **configuration-load error**. It is raised while `.zenzic.toml` is
being parsed, before any Markdown file is read and before a findings payload
exists — so the run aborts rather than reporting. A card example is executed by
running a project and requiring the code in the output; there is no output to
require, because the run never reaches the stage that produces one.

The fixture exists (`zenzic lab z001`) and is correct: it shows the invalid
configuration and the error panel. What it cannot do is appear in `findings[]`,
`--format json` or SARIF, which is why `tests/test_gallery_code_coverage.py`
records it under `CANNOT_BE_OBSERVED` rather than pretending otherwise.
