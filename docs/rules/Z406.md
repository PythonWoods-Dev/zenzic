## Rationale

This rule validates alternate-language links against the Virtual Site Map — `extra.alternate` entries in `mkdocs.yml` (mkdocs-material's language-switcher configuration), or `[project.extra].alternate` in `zensical.toml` (the structurally identical native Zensical mechanism — same `name`/`link`/`lang` shape per entry). Zenzic projects the full set of URLs the active build engine will actually generate, then checks that every alternate link resolves to one of them. If a link doesn't correspond to any URL in that map, it is a build-time 404 regardless of why it was written that way.

This is a real-URL check, not a nav-tree structure check: `Z406` does not validate `mkdocs.yml`'s `nav:` section at all.

Which config file and field are read depends on the active engine (`[build_context].engine` in `.zenzic.toml`) — `mkdocs.yml`'s `extra.alternate` for `mkdocs`, `zensical.toml`'s `[project.extra].alternate` for `zensical`.

---

## How to Fix

Point the `extra.alternate` entry at a path that actually resolves to a source file in the Virtual Site Map:

```yaml title="mkdocs.yml"
# BAD: 'fr' link points to a page that doesn't exist in the VSM
extra:
  alternate:
    - name: Français
      link: /fr/getting-started/
      lang: fr
```

```yaml title="mkdocs.yml"
# GOOD: link matches a real generated URL (e.g. docs/fr/getting-started.md exists)
extra:
  alternate:
    - name: Français
      link: /fr/getting-started/
      lang: fr
```

The same fix applies to `zensical.toml`'s `[project.extra].alternate`, entry for entry:

```toml title="zensical.toml"
# GOOD: link matches a real generated URL
[project.extra]
alternate = [
  { name = "Français", link = "/fr/getting-started/", lang = "fr" },
]
```

## Configuration

```yaml title="mkdocs.yml"
extra:
  alternate:
    - name: English
      link: /
      lang: en
    - name: Français
      link: /fr/
      lang: fr
```

```toml title="zensical.toml"
[project.extra]
alternate = [
  { name = "English", link = "/", lang = "en" },
  { name = "Français", link = "/fr/", lang = "fr" },
]
```

## Suppression & Governance

Because `Z406` is a global topology rule evaluated against the Virtual Site Map, it **CANNOT** be suppressed via inline comments (`<!-- zenzic:ignore: Z406 -->`) — this is enforced by `NON_INLINE_SUPPRESSIBLE_CODES` (ADR-093). If you add an inline directive anyway, `Z406` still fires and the dead directive itself is reported as `Z603 DEAD_SUPPRESSION`, pointing you back here.

Fix the alternate-link entries in your active engine's config file — `mkdocs.yml`'s `extra.alternate` or `zensical.toml`'s `[project.extra].alternate`, depending on `[build_context].engine` in `.zenzic.toml`.
