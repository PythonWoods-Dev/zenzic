## Rationale

This rule validates `extra.alternate` entries in `mkdocs.yml` — mkdocs-material's language-switcher configuration — against the Virtual Site Map. Zenzic projects the full set of URLs the build engine will actually generate, then checks that every `extra.alternate` link resolves to one of them. If a link doesn't correspond to any URL in that map, it is a build-time 404 regardless of why it was written that way.

This is a real-URL check, not a nav-tree structure check: `Z406` does not validate `mkdocs.yml`'s `nav:` section at all.

`Z406` is mkdocs-material-specific by design, not an adapter-agnosticism gap: Zensical projects don't currently benefit from this check because Zensical has no equivalent to `extra.alternate` — its own i18n model declares locale content structurally inside `docs_dir` rather than as a separate list of alternate-language links to validate.

---

## How to Fix

Point the `extra.alternate` entry at a path that actually resolves to a source file in the Virtual Site Map:

```yaml title="mkdocs.yml"
# BAD: 'fr' link points to a page that doesn't exist in the VSM
extra:
  alternate:
    - name: Français
      link: /fr/getting-started/
      lang: fr
```

```yaml title="mkdocs.yml"
# GOOD: link matches a real generated URL (e.g. docs/fr/getting-started.md exists)
extra:
  alternate:
    - name: Français
      link: /fr/getting-started/
      lang: fr
```

## Configuration

```yaml title="mkdocs.yml"
extra:
  alternate:
    - name: English
      link: /
      lang: en
    - name: Français
      link: /fr/
      lang: fr
```

## Suppression & Governance

Because `Z406` is a global topology rule evaluated against the Virtual Site Map, it **CANNOT** be suppressed via inline comments (`<!-- zenzic:ignore: Z406 -->`) — this is enforced by `NON_INLINE_SUPPRESSIBLE_CODES` (ADR-093). If you add an inline directive anyway, `Z406` still fires and the dead directive itself is reported as `Z603 DEAD_SUPPRESSION`, pointing you back here.

Fix the `extra.alternate` entries in your site's `mkdocs.yml` — this check reads `mkdocs.yml` only; it does not read `zensical.toml`.
