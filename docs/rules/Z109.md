## Rationale

`Z109` is defined in the finding-codes catalog to describe a remote HTTP/HTTPS
link that returns a 4xx/5xx HTTP status code or fails due to a network
connection timeout or DNS resolution error. The current engine consolidates
this condition under the shared **`Z101` LINK_BROKEN** code rather than
emitting `Z109` — external link failures surface as `Z101`, alongside broken
internal links, missing files, and other unreachable-link conditions (see
[`Z101`](Z101.md)).

---

## Activation

`Z109` is a **catalogued alias and is never emitted**. The condition it names — an unreachable
external URL — is evaluated only under the `--strict` flag on `check links` and `check all`, and
every failure is reported as **`Z101` LINK_BROKEN**, charged at `Z101`'s **8.0 points**. The 3.0
above is the catalogue entry; no finding is ever scored against it:

```bash
# External HTTP validation ACTIVE — failures are reported as Z101
zenzic check all --strict
zenzic check links --strict
```

Without `--strict`, Zenzic resolves only internal links (Pass 1 and Pass 2). External HTTP validation (Pass 3) is skipped entirely.

---

## Reserved documentation hostnames are never checked

Independently of `--strict` and `--no-external`, Zenzic never issues an HTTP request for a
hostname [RFC 2606](https://www.rfc-editor.org/rfc/rfc2606) reserves for documentation.
These names exist so that documentation can show a URL that is guaranteed *not* to reach a
real server, so a failure to reach one carries no information — it is the expected result:

| Reserved | Examples |
| --- | --- |
| Top-level domains (§2) | `anything.test`, `anything.example`, `anything.invalid`, `anything.localhost` |
| Second-level domains (§3) | `example.com`, `example.net`, `example.org`, and any subdomain |

Matching is on the parsed hostname, never on a substring of the URL, so a real domain that
merely resembles a reserved one is still checked: `notexample.com`, `example.company`,
`myexample.net` and `example.com.evil.net` are all validated normally.

This is a product default with no configuration to disable it. To skip a *real* hostname,
use `excluded_external_urls` below; the two mechanisms are independent, and a prefix
declared there is still recorded as used even when the URL is also reserved, so it will not
be reported stale by [`Z620`](Z620.md).

## Bypass: `--no-external`

To retain the warning-promotion behavior of `--strict` while **disabling network I/O**, combine it with `--no-external`:

```bash
# External HTTP validation SUPPRESSED — no outbound HTTP requests
# All other --strict behaviors (warning promotion, Dead Definitions as errors) remain active
zenzic check all --strict --no-external
```

This is the recommended pattern for air-gapped CI environments or developer machines where external URL reachability is confirmed by other means.

## Configuration

To permanently exclude known rate-limited or private URLs from Z109 evaluation (without disabling the check globally):

```toml
# .zenzic.toml - Ignore rate-limited or private external domain URLs
excluded_external_urls = [
    "https://github.com",
    "https://api.github.com",
]
```
