# Z405: UNUSED_ASSET

    ---

    Penalty: **3.0 points** | Category: **`brand`**

- :material-cog-sync-outline:{ .lg .middle style="color: #64748b;" } **Remediation & Opt-In**

    ---

    Auto-Fixable: **No** | Opt-In: **No**

## Rationale

This rule is triggered when an image or static asset file stored in `assets/` is never referenced by any Markdown document across the Virtual Site Map, leading to unnecessary repository bloat. A reference counts if it appears as a standard Markdown link (`[text](path)`), an HTML `<img src>`/`<a href>` tag, an AST reference-link definition, or the page's own `image:` frontmatter key (e.g. a social/OG card image). A design-source file that is never itself referenced by any page — for example an SVG a social card image was exported from, where only the exported PNG appears in frontmatter — is not recognized and needs explicit exclusion — see [Configure Social Metadata & SEO](../how-to/configure-social-metadata.md) and Configuration below.

---

## How to Fix

Inspect the flagged location in the Markdown file and update the content or configuration:

<div class="grid cards" markdown>

- :material-close-circle:{ .lg .middle style="color: #ef4444;" } **Failing Pattern (Triggers Z405)**

    ---

    ```text title="docs/example.md"
    docs/assets/images/obsolete-logo.png -> File exists on disk but never linked in markdown.
    ```

- :material-check-circle:{ .lg .middle style="color: #10b981;" } **Passing Pattern (Resolves Z405)**

    ---

    ```markdown title="docs/example.md"
    <!-- GOOD: Reference asset in documentation page or delete obsolete asset -->
    ![Project Logo](../assets/images/logo.png)
    ```

</div>

## Suppression & Governance

Because `Z405` is a project-level asset hygiene rule evaluated across all repository files, it **CANNOT** be suppressed via inline comments (`<!-- zenzic:ignore: Z405 -->`) — this is enforced by `NON_INLINE_SUPPRESSIBLE_CODES` (ADR-093). If you add an inline directive anyway, `Z405` still fires and the dead directive itself is reported as `Z603 DEAD_SUPPRESSION`, pointing you back here.

To keep an unreferenced asset file intentionally (for example, dynamic assets loaded via JavaScript or branding kits), exclude it via `excluded_dirs` or `directory_policies` in `.zenzic.toml`:

```toml
[governance.directory_policies]
"docs/assets/branding/**" = ["Z405"]
```
