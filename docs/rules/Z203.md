## Rationale

This critical security incident rule (Exit 3) is emitted when a path specifier attempts to escape the repository workspace to access sensitive OS system directories (such as `/etc/passwd` or `/proc/`).

The check reads the link the way a browser or server resolves it, not as raw text. Percent-encoded spellings (`..%2f..%2fetc%2fpasswd`, `%2e%2e%2f`), repeated encoding (`..%252f`), mixed-case escapes and backslash separators are decoded and normalised first. Every spelling of the same destination therefore raises the same Exit 3.

Classification is by where the path *lands* after normalisation, not by what its text contains, and it never consults the filesystem — the same link produces the same verdict whether or not anything exists at the target. A relative link whose text mentions a system-root-like name but that still resolves inside `docs_dir` — for example `../../guide/usr/manual.md` — raises no finding of this kind at all. A relative link that escapes `docs_dir` but still lands inside the repository is `Z202`, a boundary crossing rather than an OS-traversal target. A relative link that leaves the repository reaches `Z203`.

A **site-absolute** link is the one case arithmetic cannot settle: `/etc/passwd` and a genuine documentation section at `/etc/` both map inside `docs_dir` by construction. Such a link reaches `Z203` whenever its first segment names an OS system directory, and the way to declare a real section legitimate is [`absolute_path_allowlist`](../reference/configuration-reference.md) — a declaration a reviewer sees in a diff. Before v0.31.0 the engine instead resolved the target and downgraded the finding when a file happened to exist there, which made the verdict depend on repository content: creating `docs/etc/passwd` with any contents turned every `/etc/passwd` link in the corpus into an ordinary `Z202`.

The whole document is in scope for this check, including text inside HTML and MDX comments, inside inline math spans, and after an unterminated code fence. Those constructs are ignored by the *quality* checks — a broken link in a comment is not a broken link — but a security payload is no less real for being written in one. The single exception is a **closed, well-formed code fence**, which stays out of scope so that documentation can show a payload as an example; see [Two Masks, Two Questions](../explanation/discovery.md#two-masks).

## How to Fix

Inspect the flagged location in the Markdown file and update the content or configuration:

<div class="grid cards" markdown>

- :material-close-circle:{ .lg .middle style="color: #ef4444;" } **Failing Pattern (Triggers Z203)**

    ---

    ```markdown title="docs/example.md"
    <!-- BAD: Attempting to access OS system file -->
    Read [System Passwd](../../../../../../etc/passwd).
    ```

- :material-check-circle:{ .lg .middle style="color: #10b981;" } **Passing Pattern (Resolves Z203)**

    ---

    ```markdown title="docs/example.md"
    <!-- GOOD: Reference files inside the repository workspace -->
    Read [Local Configuration](../config/settings.json).
    ```

</div>
