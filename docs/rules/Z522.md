## Description

A table cell value contains a string outside the allowed enumerated whitelist configured in `[policies].table_cell_enums`.

When Markdown tables document status fields, lifecycle stages, or severity levels, typo-laden or unstandardized strings (e.g. `unverified`, `in-progress`, `unknown`) degrade documentation fidelity and break automated parsers.

---

## Configuration

Declare allowed enum values per column header in `.zenzic.toml`:

```toml title=".zenzic.toml"
[policies.table_cell_enums]
"Status" = ["draft", "review", "stable", "deprecated"]
"Severity" = ["low", "medium", "high", "critical"]
```

```toml title="pyproject.toml"
[tool.zenzic.policies.table_cell_enums]
"Status" = ["draft", "review", "stable", "deprecated"]
"Severity" = ["low", "medium", "high", "critical"]
```

Values are compared case-insensitively and ignore markdown code backticks (e.g., `` `stable` `` matches `stable`).

---

## How to Fix

Update the table cell to use one of the approved enum values:

```markdown
<!-- Before (Disallowed enum value 'unverified') -->
| Module | Status |
| :--- | :--- |
| Auth Engine | unverified |

<!-- After (Approved enum value 'draft') -->
| Module | Status |
| :--- | :--- |
| Auth Engine | `draft` |
```
