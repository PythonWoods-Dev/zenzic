## Rationale

This system rule is emitted when an external plugin rule or custom extension module raises an unhandled runtime exception during static document analysis.

To ensure build pipeline stability, Zenzic isolates execution failures within third-party rule handlers, logging a Z901 finding with the exception stack trace rather than crashing the overall auditing process.

---

## How to Fix

Inspect the error details in the CLI execution output, identify the failing custom plugin handler, and address the unhandled edge case or syntax error within the plugin's Python source code.

There is no suppression or configuration key for `Z901` — it reports at `line_no=0` (the finding isn't tied to a specific line of content), so an inline `<!-- zenzic:ignore:Z901 -->` comment has no line to attach to. The only real remedy is fixing (or removing) the plugin rule that raised the exception.

---

## Why there is no gallery example

Every other finding code has a runnable fixture under `zenzic lab`. This one
does not, and the reason is worth stating so the absence does not read as an
oversight.

`Z901` fires when a **plugin rule raises an unexpected exception**. Demonstrating
it would mean shipping deliberately broken plugin code inside a gallery the rest
of the documentation presents as exemplary — a fixture whose whole content is an
example of what not to write, sitting beside fixtures that are examples of what
to write.

To see it in your own project: a custom rule that raises in its `check()` method
produces this code, with the rule's identity in the message.
