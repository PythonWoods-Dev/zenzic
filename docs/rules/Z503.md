## Rationale

This content quality rule is emitted when a fenced code block with a specified language tag (such as `python` or `yaml`) contains syntax errors that fail AST parsing for that language.

**Two didactic forms are recognised and skipped**, because they demonstrate a format rather than declare data:

- **A placeholder key.** `<type> = "<icon>"` names a slot a reader is meant to fill. No TOML parser accepts it — a bare key may not contain `<`. Recognition is anchored on the *key*: a placeholder in a **value** (`link = "mailto:<email-address>"`) parses and is still validated, and a **quoted** placeholder key (`"<tag>" = 1`) is valid TOML and is still validated.
- **A body that opens a fence.** A block whose first line is itself a fence opener — for example a `` ````yaml `` wrapper whose content is `` ``` { .yaml .copy } `` — is showing what a code block looks like. Parsing the display as data reports a syntax error against prose.

**A placeholder in a table header (`[<section>]`) is deliberately not recognised**, and the reason is that it is a different defect rather than the same one in another position. A placeholder *key* fails as `Invalid statement` at column 1; a placeholder *header* fails as `Invalid initial character for a key part` at column 2, and the same holds for `[project.<name>]` and `[[<item>]]`. Covering it needs a second, differently-anchored pattern, and **no such block exists in the corpora this rule was measured against** — neither in this repository nor in the foreign corpus used to size the change. It is left unhandled rather than guessed at: if you have one, the finding is a true report that this rule does not yet know how to read.

### If a snippet is skipped that should not be

The skip is a silence, so a real syntax error in a skipped block goes unreported. The two forms fail differently, and the difference matters:

- **A placeholder key degrades safely.** Only the placeholder line is neutralised; the rest of the snippet is still parsed. A block containing both `<type> = "<icon>"` and a genuine error still reports the genuine error.
- **A fenced body is skipped whole.** Nothing inside it is parsed, so broken YAML inside a `` ````yaml `` wrapper reports nothing at all.

If you need a block in the second form validated, remove the wrapper and present the inner block directly, or tag the outer block `` ```text `` so the omission is explicit rather than silent. If a block is being skipped and you cannot see why, the recognisers are `_PLACEHOLDER_KEY_RE` and the fence-opener test in `check_snippet_content`.

## How to Fix

Inspect the flagged location in the Markdown file and update the content or configuration:

### Bad (Triggers Z503)

````markdown
<!-- BAD: Invalid Python syntax in fenced code block -->
```python
def calculate_score(
```
````

### Good (Resolves Z503)

````markdown
<!-- GOOD: Valid Python syntax or use 'text' tag for partial code -->
```python
def calculate_score(penalty: float) -> float:
    return 100.0 - penalty
```
````
