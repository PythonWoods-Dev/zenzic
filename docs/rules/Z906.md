## Rationale

Informational finding emitted when Zenzic completes a directory traversal or graph discovery run without locating any Markdown or MDX source files matching the target glob pattern.

`Z906` means one specific thing: **the directory exists and holds no Markdown.** That is a
project in setup, or a tree whose every page an exclusion layer removed, and nothing is wrong
with it — hence `info` and exit `0`.

!!! warning "A directory that does not exist is a different finding"

    Until v0.31.0 a **missing** `docs_dir` produced this same finding and the same exit `0`.
    Those are two situations and only one of them is fine: a scan cannot succeed at examining
    a directory that is not there, and reporting success over it is a green gate on an
    unexamined tree. A missing `docs_dir` is now [`Z111`](Z111.md) and exits `1`.

---

## How to Fix

Nothing, in most cases — add your first page and the finding goes away.

If you did expect pages here, the directory is real and your sources are elsewhere or excluded:

```bash
# See what Zenzic resolved, and what it thinks this project is
zenzic env

# Check the target explicitly -- "check" is a command group and requires a subcommand
zenzic check all docs/
```

Then verify `docs_dir` in `.zenzic.toml`, and the `excluded_dirs` / `excluded_file_patterns`
layers, which can empty a directory that is full on disk.

## Why there is no gallery example, and where this code does not appear

Two absences, and they are different.

**No gallery fixture.** `Z906` requires a documentation directory containing no
Markdown at all. git cannot track an empty directory, and adding any placeholder
file changes the outcome — a `.txt` placeholder makes the run report `Z405`
(unused asset) instead, which was verified rather than assumed. There is no
fixture shape that produces this code and survives a commit.

**It never reaches a machine-readable format.** `Z906` is *printed* and the run
then returns before a findings payload is assembled. It will therefore never
appear in `findings[]`, in `--format json`, or in SARIF — only in the terminal.
A CI step parsing JSON to decide whether an audit ran cannot detect this
condition; the signal it needs is the absence of findings combined with a zero
file count, both of which the summary reports.
