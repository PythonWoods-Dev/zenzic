# Z511: EXCESSIVE_SENTENCE_LENGTH

<div class="grid cards" markdown>

- :material-alert-outline:{ .lg .middle style="color: #f59e0b;" } **Severity: Warning**

    ---

    Penalty: **1.0 points** | Category: **`content`**

- :material-cog-sync-outline:{ .lg .middle style="color: #64748b;" } **Remediation & Opt-In**

    ---

    Auto-Fixable: **No** | Opt-In: **No**

</div>

---

## Description

A prose sentence exceeds the configured maximum word count threshold (default: 40 words).

Extremely long sentences reduce reader comprehension, increase cognitive load, and hurt technical documentation readability.

---

## How to Fix

1. Break the sentence into two or more shorter sentences using punctuation (`.`, `;`).
2. Use bullet points or lists to structure complex multi-part statements.

---

## Configuration

You can configure the maximum allowed sentence length in `.zenzic.toml`:

```toml title=".zenzic.toml"
max_sentence_length = 35
```

```toml title="pyproject.toml"
[tool.zenzic]
max_sentence_length = 35
```

---

## Suppression

To suppress this warning for a specific sentence, add an inline comment directive at the end of the offending line:

The directive belongs **at the end of the line the finding is on**. Placed on the
line above it suppresses nothing and is itself reported as
[`Z603 DEAD_SUPPRESSION`](Z603.md). MDX files accept the JSX comment form as well,
and the two behave identically — same placement, same effect:

```markdown title="Markdown"
<!-- zenzic:ignore:Z511 -->
```

```markdown title="MDX"
{/* zenzic:ignore:Z511 */}
```
