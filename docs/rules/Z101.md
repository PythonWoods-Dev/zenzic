# Z101: LINK_BROKEN

## Rationale

This rule validates every relative Markdown link against the Virtual Site Map (VSM) rather than just checking filesystem disk presence. A finding is emitted when a target page does not exist in the VSM or is unserved by the build engine.

Linking to non-existent target files or unrendered routes produces broken HTTP 404 navigation errors for end users upon site publication.

---

### `data-zenzic-ignore` does not suppress it

`Z101` is decided against the Virtual Site Map, which is a fact about the whole
project rather than about one tag, so the `data-zenzic-ignore` attribute does not
reach it — a tag carrying the attribute still raises `Z101` when its target is not
in the map. The same tag's `Z104` **is** suppressed by it, so one missing target
can leave one of its two codes reported:

```html
<!-- Z104 suppressed, Z101 still reported -->
<a href="./gone.html" data-zenzic-ignore>Gone</a>
```

Use an inline `<!-- zenzic:ignore: Z101 -->` comment on the same line, or
`.zenzic.toml` governance, to silence `Z101` itself. A directive that silences
nothing is reported as [`Z603`](Z603.md).

## How to Fix

Inspect the flagged location in the Markdown file and update the content or configuration:

## Configuration

```toml title=".zenzic.toml"
# .zenzic.toml - Exclude specific external domain URLs from broken link checks
excluded_external_urls = [
    "https://github.com/PythonWoods-Dev/zenzic",
]
```

```toml title="pyproject.toml"
[tool.zenzic]
excluded_external_urls = [
    "https://github.com/PythonWoods-Dev/zenzic",
]
```

### External links are reported as `Z101`, not `Z109`

`Z109 EXTERNAL_LINK_BROKEN` appears in the finding-codes catalogue, but the engine never
emits it: every unreachable link — internal or external — is reported under `Z101`, and
charged at `Z101`'s penalty. `Z109` is a catalogue alias kept so that `zenzic lab z109` and
its gallery entry keep resolving. See [`Z109`](Z109.md) for the full account.

### Reserved documentation hostnames are never probed

[RFC 2606](https://www.rfc-editor.org/rfc/rfc2606) reserves a set of names so that
documentation can show a URL without ever pointing at a real server. Zenzic skips
external validation for all of them, because a name guaranteed not to resolve can only
ever produce a false `Z101`:

| Reserved | Examples |
| --- | --- |
| Top-level domains (§2) | `anything.test`, `anything.example`, `anything.invalid`, `anything.localhost` |
| Second-level domains (§3) | `example.com`, `example.net`, `example.org`, and any subdomain of them |

The match is on the parsed hostname, not on a substring of the URL, so a real domain that
merely resembles a reserved one is still checked — `notexample.com`, `example.company`,
`myexample.net` and `example.com.evil.net` are all validated normally.

There is no configuration to re-enable probing of a reserved name. If you need a URL
checked, use a hostname that is not reserved; if you need a real hostname *skipped*, that
is what `excluded_external_urls` above is for. The two mechanisms are independent, and a
prefix you declare there is still recorded as used even when the URL is also reserved, so
it will not be reported stale by `Z620`.
