# Z105: ABSOLUTE_PATH

## Rationale

This rule is triggered when internal links or asset paths use absolute filesystem paths or root-relative paths (e.g. `/docs/setup.md` or `C:\project\docs\setup.md`).

Absolute paths break portability across different operating systems, CI build runners, and subpath web deployments.

---

### Suppressing it on an HTML tag

When the link is written as a raw HTML tag rather than Markdown, the
parameterless `data-zenzic-ignore` attribute on that tag suppresses `Z105`:

```html
<a href="/absolute/path.md" data-zenzic-ignore>Label</a>
```

This works only for an HTML tag — a Markdown link carries no attribute to put it
on, and is governed by an inline `<!-- zenzic:ignore: Z105 -->` comment or by
`.zenzic.toml` instead. The attribute covers the HTML hygiene tier
(`Z120`–`Z124`) and the relative-link tier (`Z102`, `Z104`, `Z105`); it does
**not** cover [`Z101`](Z101.md), which is decided against the Virtual Site Map
rather than against the tag. **A tag with a missing `.md`-page target can
therefore raise `Z101` with the attribute present** — the two codes are
suppressed by different mechanisms. An attribute that suppresses nothing is
itself reported as [`Z603`](Z603.md).

## How to Fix

Inspect the flagged location in the Markdown file and update the content or configuration:

<div class="grid cards" markdown>

- :material-close-circle:{ .lg .middle style="color: #ef4444;" } **Failing Pattern (Triggers Z105)**

    ---

    ```markdown title="docs/example.md"
    <!-- BAD: Absolute root-relative path specifier -->
    Read the [Setup Guide](/docs/how-to/setup.md).
    ```

- :material-check-circle:{ .lg .middle style="color: #10b981;" } **Passing Pattern (Resolves Z105)**

    ---

    ```markdown title="docs/example.md"
    <!-- GOOD: Portable relative path calculated from source file -->
    Read the [Setup Guide](../how-to/setup.md).
    ```

</div>
