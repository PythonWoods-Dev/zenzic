## Rationale

This rule is emitted when a global governance rule declared in `.zenzic.toml` never matched anything during a full workspace scan — one of four sources: a `[governance.directory_policies]` entry, a `[governance.per_file_ignores]` entry, an `excluded_file_patterns` glob, or an `excluded_external_urls` entry.

Stale suppressions mask real configuration intent and violate the Zero-DBT invariant by accumulating dead technical debt.

---

## How to Fix

`Z620` has no Markdown-file location — the flagged location is always `.zenzic.toml` itself. Find the specific stale entry named in the finding message and remove it:

- A `[governance.directory_policies]` pattern whose codes were never actually suppressed anywhere.
- A `[governance.per_file_ignores]` pattern whose codes were never actually suppressed anywhere.
- An `excluded_file_patterns` glob that never matched any file during traversal.
- An `excluded_external_urls` entry that was never skipped because the URL was never encountered.

## Configuration

```toml title=".zenzic.toml"
# Audit and remove stale entries under [governance.directory_policies]

"docs/blog/**" = ["Z410", "Z411"]
```

```toml title="pyproject.toml"
[tool.zenzic.governance.directory_policies]
"docs/blog/**" = ["Z410", "Z411"]
```

## Suppression & Governance

Because `Z620` is a meta-governance rule detecting stale configuration rules in `.zenzic.toml`, it **CANNOT** be suppressed via inline comments (`<!-- zenzic:ignore: Z620 -->`).

To resolve `Z620`, remove the dead or unused suppression rule from `.zenzic.toml`.
