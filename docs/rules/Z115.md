# Z115: STALE_ROUTE_MANIFEST

<div class="grid cards" markdown>

- :material-alert-outline:{ .lg .middle style="color: var(--zz-warning);" } **Severity: Warning**

    ---

    Penalty: **1.0 points** | Category: **`structural`**

- :material-cog-sync-outline:{ .lg .middle style="color: var(--zz-terminal-meta);" } **Remediation & Opt-In**

    ---

    Auto-Fixable: **No** | Opt-In: **No**

</div>

---

## Rationale

The `prebuilt` engine does not compute URLs. It reads them from a routing table
your site generator writes to `.zenzic-vsm.json`. That file is a second copy of
a fact, and a second copy goes stale: add a page without re-running the
generator and the manifest no longer describes the site.

A source the manifest does not declare routes as `IGNORED`. Every link pointing
at it is then reported `Z101` as unreachable — an error on a link that is
correct, about a page that exists. Z115 is the finding that names the cause,
because without it the run points at the link and the repair it implies is the
wrong one.

Only an engine reading a declared routing table can raise this. `standalone`
derives each URL from the path it has just read, so there is no second copy to
fall behind and no drift to report.

## How to Fix

<div class="grid cards zz-pattern-pair" markdown>

- :material-close-circle:{ .lg .middle style="color: var(--zz-error);" } **Failing Pattern (Triggers Z115)**

    ---

    ```json title=".zenzic-vsm.json"
    // BAD: docs/guide.md is on disk and absent here
    {
      "index.md": { "url": "/", "status": "REACHABLE" }
    }
    ```

- :material-check-circle:{ .lg .middle style="color: var(--zz-success);" } **Passing Pattern (Resolves Z115)**

    ---

    ```json title=".zenzic-vsm.json"
    // GOOD: regenerated after the page was added
    {
      "index.md": { "url": "/", "status": "REACHABLE" },
      "guide.md": { "url": "/guide/", "status": "REACHABLE" }
    }
    ```

</div>

If the manifest is produced during your CI build rather than committed,
generate it **before** `zenzic check` runs in the same job — a manifest written
afterwards has no effect on that run.

If nothing in your project writes a manifest, `prebuilt` is the wrong engine.
Switch to `standalone`.
