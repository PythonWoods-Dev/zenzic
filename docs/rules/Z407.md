## Rationale

MkDocs' `not_in_nav`, `exclude_docs` and `draft_docs` take gitignore-style patterns in a single multiline string. When a pattern cannot be parsed, MkDocs refuses to build at all — `Invalid git pattern`, `Aborted with a configuration error!`.

Zenzic cannot follow it there. An analyser that aborts on a bad pattern denies the reader every other finding in the repository, so the pattern is reported and the scan continues.

What this replaces is silence. Before `Z407` the declaration simply had no effect: the page the author meant to declare stayed an orphan, `Z402` still fired, and nothing said why.

The penalty is **0.0** deliberately. The configuration is wrong, but no document is worse for it.

---

## How to Fix

<div class="grid cards zz-pattern-pair" markdown>

- :material-close-circle:{ .lg .middle style="color: #ef4444;" } **Failing Pattern (Triggers Z407)**

    ---

    ```yaml title="mkdocs.yml"
    # BAD: an unterminated POSIX character class — gitignore syntax cannot parse it
    not_in_nav: |
      [[:bad:]
    ```

- :material-check-circle:{ .lg .middle style="color: #10b981;" } **Passing Pattern (Resolves Z407)**

    ---

    ```yaml title="mkdocs.yml"
    # GOOD: a literal path, or a valid glob
    not_in_nav: |
      archive.md
      developers/records/*
    ```

</div>

---

## What is *not* reported

A pattern that parses but matches nothing is **not** a `Z407`. `docs/[orphan.md` compiles to a literal string no file will ever equal, and from the outside that is indistinguishable from a pattern whose targets have all been fixed — the ordinary end state of an exemption. A declaration that silences nothing is reported as [`Z620`](Z620.md) instead.

---

## Suppression & Governance

Because `Z407` is a configuration-file defect with no document line to anchor to, it **CANNOT** be suppressed via inline comments (`<!-- zenzic:ignore: Z407 -->`). Correct the pattern in `mkdocs.yml`, or remove the key.
