## Rationale

This rule is an informational telemetry signal emitted when two or more documentation pages form a direct circular navigation loop through relative links.

While not fatal to static site rendering, cyclic navigation loops can confuse readers and degrade automated search engine crawler traversal.

### Why this check is opt-in

**A link cycle is documentation's ordinary shape, not a defect signal.** An index links to each of its records and every record links back to the index; two articles cross-reference each other's arguments; a reference section interlinks densely. All three are good practice, and all three are cycles.

That is a measurement, not an opinion. Run against this project's own documentation, the rule reported **704 findings across 238 of roughly 300 pages** — 79% of the corpus — from 17 strongly connected components, eleven of them simple mutual pairs and one spanning 44 interlinked developer-reference pages. The instances sampled were the `adr-vault/index.md` ↔ `records/adr-09x.md` pattern, which every documentation set with an index has by construction.

Left on by default, the practical response was to silence it for an entire directory tree, which is worse than not running it: nobody can then tell whether the cycles are harmless or real, and nobody revisits the decision.

So the check is **off unless you ask for it**. Enable it for a corpus that is meant to be an acyclic hierarchy — an ordered tutorial sequence, a linear handbook — where a cycle genuinely means a reader can be sent in a loop:

```toml
[policies]
enable_circular_link_check = true
```

See [`enable_circular_link_check`](../reference/configuration-reference.md#enable_circular_link_check) in the configuration reference.

## How to Fix

Inspect the flagged location in the Markdown file and update the content or configuration:

<div class="grid cards zz-pattern-pair" markdown>

- :material-close-circle:{ .lg .middle style="color: var(--zz-error);" } **Failing Pattern (Triggers Z106)**

    ---

    ```markdown title="docs/example.md"
    <!-- page-a.md links to page-b.md -->
    See [Section B](page-b.md).

    <!-- page-b.md links back to page-a.md -->
    Return to [Section A](page-a.md).
    ```

- :material-check-circle:{ .lg .middle style="color: var(--zz-success);" } **Passing Pattern (Resolves Z106)**

    ---

    ```markdown title="docs/example.md"
    <!-- Restructure navigation to form a linear/hierarchical reading path -->
    See [Section B](page-b.md).
    ```

## Why the editor does not underline it

`Z106` is a **note**-severity finding: `CODE_DEFINITIONS` records `note`, which the
reporting layer surfaces as `info`, with penalty 0.0. The language server deliberately
does not send note-level diagnostics to the editor. The PROBLEMS panel is reserved for
what a reader has to act on, and the CLI report is the authoritative record of the rest.

**Where a project that opts in actually sees it** — measured on a two-page mutual
reference, not inferred. Default human output: **not shown**. `--show-info`: shown.
`--format json` and `--format sarif`: present. VS Code: not shown. So CI that parses the
machine formats sees every cycle, and a person running `zenzic check all` without
`--show-info` sees none — which is the same threshold the editor applies, reached by a
different mechanism.

That is a property of the severity, not of the code, and it applies identically to the
other three note-level findings (`Z123`, `Z401`, `Z906`). The editor **does** compute
the cycles — the same graph pass the CLI runs — so nothing is missing from its model of
the site; the finding is simply below the threshold the transport carries.
